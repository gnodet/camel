# Loop Constraints — Apache Camel PR Review Loop

## Push & Merge

- NEVER merge, close, or label any PR
- NEVER push to any branch (review-only loop)
- NEVER approve own PRs (gnodet) — use COMMENT event
- Reviews from gnodet must be addressed but do NOT count as human approvals

## Scope

- Max 5 PRs per run
- No size limit on individual PRs
- Exclude draft PRs
- Exclude PRs with `[DO NOT MERGE]` title prefix

## Review Quality

- Always verify findings before posting (maker/checker pattern)
- Always check git history of modified files (git log, git blame)
- Review against project rules from `.oss-ai-helper-rules/`
- Follow CLAUDE.md project-specific rules (testing, Awaitility, MockEndpoint, etc.)

## Paths

- Ignore generated code styling (`src/generated/`)
- Pay extra attention to security-sensitive paths (consumers, type converters, data formats)

## Communication

- AI attribution required: "_Claude Code review on behalf of @gnodet_"
- AI disclaimer required: "_This review was generated by an AI agent and may contain inaccuracies. Please verify all suggestions before applying._"

## Budget

- 80% throttle: warn when daily budget exceeds 80%
- Kill switch: `loop-pause-all` in STATE.md
- Green-exit: if no work, skip iteration cleanly
